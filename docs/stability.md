# 2026-10-05 稳定性与资源边界复核

复核用户提供的 `c7105a3` 报告，并对当前源码建立离线复现。环境变量清空的
错误确认和 VLAN 规范化失败生成合法指纹，两项均可复现；其余项目按加固和
测试覆盖处理。报告中的“最新实机为 362c78c”已过时，后续部署及其源码、CI、
产物校验值记录在 [验证记录](validation.md)。

## 修改与接口

- 环境读取共用有超时、长度和退出状态检查的完整快照。成功读取后区分字段
  不存在、空值和非空值；失败或带诊断输出时返回不可用状态，不能用默认值
  确认写入。标准错误同样计入读取预算，避免无回调的进程接口缓冲大量错误文本。
  写入保留底层两次冗余更新，结果区分 `write` / `verify`，另返回回读原因。
  配置和恢复返回已确认、未确认、尚未执行的字段，输出不含字段值。
- 配置请求超时或出现部分保存错误后，停止再次提交，界面提供重新读取入口。
  刷新后依据当前存储值重新计算差异，不自动重交所有字段，也不自动回滚。
  多个环境变量仍不是一个原子事务。
- VLAN 查询、规范化和哈希计算分别检查退出状态。规范化用独立私有临时文件，
  输出必须是单个指纹。守护进程同样拒绝诊断文字与哈希混合的结果；查询失败
  保留上次成功状态并重试，没有增加轮询频率或常驻进程。
- 升级元数据只解析一次，取消重复的 `grep` / `cut`。控制文件上限 4 KiB，
  拒绝重复字段，支持 `basic` / `bfw`，新构建声明 `FW_TARGET=WAS-110`。
  兼容旧包无目标字段的格式，但检查 MIPS Linux uImage 的头部、长度和两项 CRC，
  以及 SquashFS v4 的头部和声明长度。格式检查不能证明全部 RootFS 文件可启动，
  也不代替槽检查和试启动。
- 升级包上限 128 MiB；内核和 Bootcore 各不超过 8 MiB，RootFS 不超过 32 MiB。
  组件的实际大小和 SHA-256 全部通过后，才修改目标有效标志或写入闪存。
  Web 和 CLI 共用安装器；Web 在解析 multipart 前额外预算上传及复制的共存空间。
- 公共资源限制集中在 `8311-limits.sh`。安装后的 Shell 工具直接共用，Lua 的
  上传预检通过固定命令调用；升级包安装器构建时嵌入同一份源码，因此能从
  没有该模块的旧固件运行。没有从待验证归档中加载或执行辅助代码。
- `/tmp` 空间与可用内存共同检查，另留 8 MiB 运行余量。目标设备的 tmpfs
  报告零可用块，因此不能仅用 `df` 判断不足。预检后仍逐项检查写入错误。
- 支持包单项输出上限 1 MiB，数据和压缩归档各不超过 8 MiB，生成前预算
  16 MiB 暂存空间。原始 pontop 自行生成的文件也受限制。超限、超时或查询
  失败丢弃不完整结果，明确报错，不发布部分包或旧原始包。默认脱敏与显式
  `--raw` 保留。
- uImage 校验和闪存读回采用 FIFO 流式计算，分别检查读取和校验命令状态，
  不复制整份读回组件，也不依赖 `pipefail`。闪存写入没有短强制终止超时。

## 验证方式

离线回归覆盖正常清空、回读失败与超时、部分输出后失败、畸形快照、Base64、
规范化失败、临时文件失败、哈希失败和混合输出；另覆盖控制文件、兼容标识、
组件格式、CRC、空间不足、输出快速增长、失败读回与失败后规则状态恢复。

Linux CI 使用真实 `flock` 和子进程测试两个升级进程、支持包生成与删除，以及
超时后的锁持有行为。配置保存与恢复执行实际 Lua 控制器，只有硬件写入替换
为测试数据，锁用真实 POSIX 文件锁，两个顺序均检查互斥。目标设备的独立 RAM
锁探针已确认 nixio `tlock` 与 `flock` 是不同锁类型，不能互换来证明互斥。
这些测试不访问真实 UBI / MTD。

Windows 不支持 Linux 文件大小限制，原生 Python 也不能继承 MSYS FIFO。
本地测试对这两个接口使用文件适配，只验证结果和错误传播；真实限制、FIFO
和并发结论必须以 Linux CI 为准。构建、浏览器和目标设备结果分别记录，
不会从静态测试推导光纤线路性能。

## 发布与线路验证

构建清单记录完整源提交、目标、CI 地址、固定底包和组件哈希；对应实机结果
保存在验证记录中。Actions 的 30 天保留期适合候选包。稳定发布需要固定一个
已经完成相应验证的候选，以 Release 保存固件、校验值、清单和已知问题。
本轮没有把未经线路验证的包宣称为稳定版，也未新增发布者签名。

PON 注册、Internet、IPTV、重新注册后的规则恢复和长期负载应在同一候选上
核对。管理页面、镜像校验和脚本正常不能替代这些业务测试。丢包、吞吐、延迟
或温度收益需要明确经过这台设备的测量；主力线路不执行断电、异常启动或
存储故障注入。没有修改内核、驱动、调频策略或引入动态状态缓存。
