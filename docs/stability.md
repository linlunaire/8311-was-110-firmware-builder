# 2026-10-05 稳定性与资源边界复核

复核用户提供的 `c7105a3` 报告，并对当前源码建立离线复现。环境变量清空的
错误确认和 VLAN 规范化失败生成合法指纹，两项均可复现；其余项目按加固和
测试覆盖处理。报告中的“最新实机为 362c78c”已过时，后续部署及其源码、CI、
产物校验值记录在 [验证记录](validation.md)。

## 修改与接口

- 环境读取共用超时、长度和退出状态检查，写入确认使用完整快照。成功后区分字段
  不存在、空值和非空值；失败或带诊断输出时返回不可用状态，不能用默认值
  确认写入。标准错误同样计入读取预算，避免无回调的进程接口缓冲大量错误文本。
  单字段成功查询直接使用结果；无法确认缺字段时才读取快照，超时或超限不再
  追加查询，避免把每次单字段显示都变成完整环境解析。
  写入保留底层两次冗余更新，结果区分 `write` / `verify`，另返回回读原因。
  配置和恢复返回已确认、未确认、尚未执行的字段，输出不含字段值。
- 配置请求超时或出现部分保存错误后，停止再次提交，界面提供重新读取入口。
  刷新后依据当前存储值重新计算差异，不自动重交所有字段，也不自动回滚。
  多个环境变量仍不是一个原子事务。
- VLAN 查询、规范化和哈希计算分别检查退出状态。规范化用独立私有临时文件，
  输出必须是单个指纹。守护进程同样拒绝诊断文字与哈希混合的结果；查询失败
  保留上次成功状态并重试，没有增加轮询频率或常驻进程。
- 升级元数据只解析一次，取消重复的 `grep` / `cut`。控制文件上限 4 KiB，
  拒绝重复字段，支持 `basic` / `bfw`，新构建声明 `FW_TARGET=WAS-110`。
  兼容旧包无目标字段的格式，但检查 MIPS Linux uImage 的头部、长度和两项 CRC，
  以及 SquashFS v4 的头部和声明长度。格式检查不能证明全部 RootFS 文件可启动，
  也不代替槽检查和试启动。
- 升级包上限 128 MiB；内核和 Bootcore 各不超过 8 MiB，RootFS 不超过 32 MiB。
  组件的实际大小和 SHA-256 全部通过后，才修改目标有效标志或写入闪存。
  三个目标卷各查询一次，提前确认名称、ID 与容量；缺卷或容量不足直接拒绝，
  正常升级不隐式重建或扩容卷，保留现有卷结构。
  Web 和 CLI 共用安装器；Web 在解析 multipart 前额外预算上传及复制的共存空间。
- 公共资源限制集中在 `8311-limits.sh`。安装后的 Shell 工具直接共用，Lua 的
  上传预检通过固定命令调用；升级包安装器构建时嵌入同一份源码，因此能从
  没有该模块的旧固件运行。没有从待验证归档中加载或执行辅助代码。
- `/tmp` 空间与可用内存共同检查，另留 8 MiB 运行余量。目标设备的 tmpfs
  报告零总块数及零可用块数，此时使用内存预算；总容量正常但可用为零时
  判定不足。总容量与可用容量在同一次 `df` 查询中解析，畸形或不一致的
  容量报告直接拒绝。预检后仍逐项检查写入错误。
- 支持包单项输出上限 1 MiB，数据和压缩归档各不超过 8 MiB，生成前预算
  16 MiB 暂存空间。原始 pontop 自行生成的文件也受限制。超限、超时或查询
  失败丢弃不完整结果，明确报错，不发布部分包或旧原始包。默认脱敏与显式
  `--raw` 保留。
- uImage 校验和闪存读回采用 FIFO 流式计算，分别检查读取和校验命令状态，
  不复制整份读回组件，也不依赖 `pipefail`。闪存写入没有短强制终止超时。

首轮 `aa7db33` 镜像为 6,225,920 字节，比现有 A 卷大 4 KiB，未部署。
随后将 XZ 打包块从 256 KiB 调整为 512 KiB，以改善镜像压缩和保留扩展空间。
文件内容、模式、链接和受保护二进制仍逐项核对；块大小记录进构建清单。
这会增加单块解压缓冲上限，不能称为 RAM 用量降低；目标只读挂载、试启动和
管理访问结果须通过后才能部署完成，也不能从压缩率推导线路吞吐收益。
上一轮 `3f28b37` 与本轮空间预检候选 `ccfd23d` 的 RootFS 均为
6,053,888 字节，A 卷保留 164 KiB 余量；两槽均已通过目标只读挂载、
组件读回、试启动和管理访问，各提交的完整结果见验证记录。

## 2026-10-06 启动与诊断错误传播复核

以 `5015e4b` 为复核基线，隔离复现四类 Shell 错误传播缺陷。前述 Lua 清空确认、
规则内容指纹和临时空间修复仍然成立；本轮补齐的是另外的调用路径。

- `fwenv_get` 丢弃失败读取的部分输出；安装器的启动槽读取和写后确认先检查
  命令状态，再比较值，保留底层冗余写入。槽控制器也检查回读状态。
- 一次性启动槽和镜像有效标志允许缺省，不能用单键失败表示缺失。槽控制与
  槽检查改用确认成功的完整环境快照，复用 1 MiB / 3 秒读取限制和私有暂存；
  失败拒绝确认或重启，成功且标志缺省仍兼容旧镜像。
- 槽检查从标准输入计算完整负载 CRC，先检查 CRC 工具状态，再精确比较输出，
  不接受混入诊断文字的结果。这证明失败会被拒绝，不表示曾复现损坏镜像绕过。
- 拓扑指纹逐项检查接口、桥、端口状态和哈希计算，临时快照退出时清理；无桥
  端口仍是合法空集合。检测失败停止规则应用，守护进程保留成功状态并按原有
  策略重试。固定子模块的构建补丁在两条构建路径共用，回归实际执行打补丁后的脚本。
- 原始支持包调用的 TC dump 检查接口查询与每次 TC 查询状态。空接口集合
  正常成功，失败不发布部分包；接口筛选合并为一段 awk，保留筛选范围与排序。

本轮没有增加常驻进程、状态缓存或改变检测周期。环境快照与拓扑暂存用于
确认读取完整性；不从这些改动推导吞吐、延迟、温度或设备端耗时收益。

## 开销测量

在同一台目标设备、同一 Lua 进程中交替执行旧版 `183df68` 与新版的
`fwenv_get("commit_bank")`，各 15 次，返回值均核对为 `A`。中位耗时由
38.354 ms 降为 34.417 ms，约减少 10.3%。这是已有单字段的函数级查询，
没有写入配置；不能代表完整 HTTP 请求、PON 或宽带业务的收益。单字段读取
仍检查退出状态和输出预算，清空后的确认仍必须读取完整快照。

安装器把控制文件解析集中为一次，移除原来的九次 `grep | cut`；目标卷
信息查询由六次减为三次，并在第一次写入前全部完成。读回使用流式校验，
省去组件临时副本，保持对生产者和校验器退出状态的独立检查。

## 验证方式

离线回归覆盖正常清空、回读失败与超时、部分输出后失败、畸形快照、Base64、
规范化失败、临时文件失败、哈希失败和混合输出；另覆盖控制文件、兼容标识、
组件格式、CRC、空间不足、输出快速增长、失败读回与失败后规则状态恢复。

Linux CI 使用真实 `flock` 和子进程测试两个升级进程、支持包生成与删除，以及
超时后的锁持有行为。配置保存与恢复执行实际 Lua 控制器，只有硬件写入替换
为测试数据，锁用真实 POSIX 文件锁，两个顺序均检查互斥。目标设备的独立 RAM
锁探针已确认 nixio `tlock` 与 `flock` 是不同锁类型，不能互换来证明互斥。
这些测试不访问真实 UBI / MTD。

空间预算补测覆盖零总容量、正常容量但已满、余量不足、余量充足及畸形报告。
修复前只有已满场景被错误放行；修复后均符合预期。目标 BusyBox 在内存中
运行原函数与修正函数，也确认四种边界结果；实际 `/tmp` 的总量、已用和
可用块数均为零，修正函数继续接受足够的内存预算。未填满磁盘或设备暂存。

首个原生安装检查发现 BusyBox `crc32 文件` 会在 CRC 后附加文件名，与最初
测试替身的输出不同，因此候选被头部检查拒绝。此时尚未写入有效标志或组件；
随后改为标准输入计算头部 CRC，并让替身匹配 BusyBox 的两种输出，旧源码
因此在离线测试中复现相同失败。修正后的有效输入已再次通过原生校验与安装，
损坏输入的拒绝由隔离回归验证，没有在实机注入损坏组件。

Windows 不支持 Linux 文件大小限制，原生 Python 也不能继承 MSYS FIFO。
本地测试对这两个接口使用文件适配，只验证结果和错误传播；真实限制、FIFO
和并发结论必须以 Linux CI 为准。构建、浏览器和目标设备结果分别记录，
不会从静态测试推导光纤线路性能。

保存在验证记录中。Actions 的 30 天保留期适合候选包。稳定发布需要固定一个

本轮没有把未经线路验证的包宣称为稳定版，也未新增发布者签名。

PON 注册、Internet、IPTV、重新注册后的规则恢复和长期负载应在同一候选上
核对。管理页面、镜像校验和脚本正常不能替代这些业务测试。丢包、吞吐、延迟
或温度收益需要明确经过这台设备的测量；主力线路不执行断电、异常启动或
存储故障注入。没有修改内核、驱动、调频策略或引入动态状态缓存。
