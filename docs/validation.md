- 配置保存成功后重新加载后台值，并保留结果提示；刷新时清除浏览器恢复的未提交字段和按钮禁用状态。Hook 的独立保存按钮标明“保存并应用脚本”。

还用基线源码复现了两处失败，复现全部在隔离目录中完成：

- 升级归档声明错误 rootfs 哈希时，旧版 `--install --yes` 发生了 3 次模拟 UBI 写入，打印哈希错误后仍返回 0。修改版先验证全部组件，错误输入在任何模拟写入前返回非零。

真实试启动又定位并修复了一个隔离测试未发现的问题：旧 nixio 的权限参数接受八进制数字形式或符号形式，十进制位值 `384` / `448` 会抛异常，造成备份、配置锁和上传暂存失败。已统一使用 `rw-------` / `rwx------`，测试替身也按原生权限格式校验。增强后的回归在旧代码上失败、修复后 39 组通过；设备原生接口验证了文件 0600、目录 0700。原 `9b74460` 包因此不作为最终安装包，改用 `b159a2c`。

用户随后在 Firefox 发现点击备份后转圈结束、没有文件。设备原生 LuCI HTTP 栈复现：返回 200、有效备份和附件头，但 Content-Type 仍为 `application/json`，前端按下载契约拒绝。旧 LuCI 的 `prepare_content` 不会替换已有类型；现改为显式设置备份的 `Content-Type: text/plain; charset=utf-8`。Lua 替身已改为相同的“保留首次类型”行为，旧控制器因此失败、修复后 39 组通过；设备原生 HTTP 栈复测返回正确类型和 1131 字节有效备份。补充错误类型的浏览器回归，并将 Firefox 文件下载和表单测试加入 CI 构建门禁。
